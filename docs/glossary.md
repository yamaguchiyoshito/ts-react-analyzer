# 用語集と表示記号

レポート内の記号・スケール・用語の定義を 1 か所にまとめます。  
表示の原則は「**記号 + 文字の二重表記**」です。色だけに意味を持たせないため、白黒印刷・CI ログ・色覚多様性のいずれでも判定を読み取れます。

## 判定記号 (quality レポート)

| 記号 | 状態 | 意味 |
|------|------|------|
| ○ | PASS | 自動判定指標で重大な問題が検出されていない |
| △ | WARN | FAIL ではないが、継続監視または追加対応が必要 |
| × | FAIL | 失敗指標が 1 件以上ある |
| ◐ | PARTIAL | 自動判定は通るが、手動確認待ちが残っている |
| ― | MANUAL | 自動判定指標がなく、手動証跡待ち |

JSON / CSV の機械可読値は小文字の英語 (`pass` / `warn` / `fail` / `partial` / `manual`) のまま固定です。表示 (md / html) だけが記号付きになります。

## 増減記号 (diff 系レポート)

| 記号 | 意味 |
|------|------|
| ↗ 改善 | 前回より判定または数値が良化した |
| ↘ 悪化 | 前回より判定または数値が悪化した (証跡の喪失を含む) |
| → 変化なし | 差分なし |

判定の遷移は `pass → warn ↘` のように「遷移 + 方向」で表記します。JSON の `trend` 値は `improved` / `regressed` / `neutral` のままです。

## クラスタコード

コード行数と複雑度の 3x3 マトリクス位置を示す 2 文字コードです。  
**行数帯 (S=小 / M=中 / L=大) × 複雑度帯 (1=低 / 2=中 / 3=高)** で構成します。

| コード | 行数×複雑度 | 意味 | 旧表記 |
|--------|--------------|------|--------|
| S1 | 小規模・低複雑度 | 小規模で安定 | S-L |
| S2 | 小規模・中複雑度 | 小規模だが分岐あり | S-M |
| S3 | 小規模・高複雑度 | 小規模だが高リスク | S-H |
| M1 | 中規模・低複雑度 | 中規模で管理可能 | M-L |
| M2 | 中規模・中複雑度 | 中規模で中リスク | M-M |
| M3 | 中規模・高複雑度 | 中規模で高リスク | M-H |
| L1 | 大規模・低複雑度 | 大規模だが安定 | L-L |
| L2 | 大規模・中複雑度 | 大規模で要注意 | L-M |
| L3 | 大規模・高複雑度 | 大規模で高リスク | L-H |

帯の境界: 行数は 小<=100 / 中<=300 / 大>300 (コード行数)、複雑度は 低<=6 / 中<=12 / 高>12。

旧表記 (`S-L` 等) は複雑度の L (Low) と行数の L (Large) が同じ文字で衝突し誤読を招いたため、複雑度側を数字に再符号化しました。旧表記のレポート JSON を baseline に使っても、`diff` は自動で新表記へ正規化して比較します。

## 深刻度と判定のスケール

レポートには役割の異なる 3 つのスケールが登場します。

| スケール | 値 | 使う場所 | 役割 |
|----------|-----|----------|------|
| severity | Critical / High / Medium / Low | hot spot (優先対応 Top 5) | score 合算値の帯。Critical>=120 / High>=80 / Medium>=40 / Low<40 |
| リスク | 高 / 中 / 低 | リスク概況・ファイル一覧 | 複雑度・構造・型安全性の軸ごとの 3 段階 |
| 判定 | ○ PASS / △ WARN / × FAIL / ◐ PARTIAL / ― MANUAL | quality レポート | 出荷審査の合否と証跡の状態 |

severity とリスクは「どこから直すか」の優先順位付け、判定は「出荷してよいか」の合否です。尺度としては独立しており、相互変換はしません。

## score の算出

hot spot の score は次の合算です (各行の内訳はレポートの「score の内訳」に出力されます)。

```
score = ファイル複雑度×5 + 依存数×2 + any件数×4 + Hooks数 + クラスタ重み
```

クラスタ重み: L3=18, M3=12, L2=10, S3=8, M2=6, L1=4, S2=3, その他=1。

## 品質レポートの用語

- **親指標 / 派生指標** — 「親」はカテゴリ判定と件数集計に使う主指標。「派生」は親の内訳 (例: Route/Feature/Form/UI 別テスト対応率) で、総合判定と gate には使わない診断情報
- **自動 / 手動** — 実績ファイルから自動判定できる指標か、手動証跡 (`quality.manual.json`) の投入が必要な指標か
- **信頼度** — 高=実測/集計、中=静的推定、低=手動入力または未収集

## 表記規則

- 機械可読な識別子 (指標 ID、JSON の enum 値、CSV の Verdict 列) は英語のまま固定し、baseline 互換を保つ
- 人間向け表示 (md / html) は日本語 + 記号を使う
- 指標 ID の一覧は [品質レポート](quality.md#指標-id-一覧) を参照
